# Essentials: the code that runs the robot

These are copies of the C++ and Arduino files that make the robot drive, both on the real
Arduino and inside the simulator. Everything else in the repository (tests, the web page, the
build scripts) is support around these files. This folder is generated by
`scripts/sync_essentials.sh`: edit the originals in `firmware/` and `sim/`, then rerun the script.

## Reading order

1. **`config.h`**: every number the robot believes about itself: geometry, speed limits,
   control gains. Read this first, so the other files make sense.
2. **`mathlite.h`**: sin, cos and sqrt without a C library, so the code also builds for WebAssembly.
3. **`track.h`, `track.cpp`**: how a route is written. `Straight`, `LeftArc`, `RightArc` and `Gap`
   build a list of segments, and `curvatureAt(s)` tells you how sharply the route bends at distance `s`.
4. **`maps.h`, `maps.cpp`**: the six routes the robot can run.
5. **`planner.h`, `planner.cpp`**: the racing speed profile. It sets the fastest safe speed at every
   point of the route, from a grip limit and forward and backward passes for acceleration and braking.
6. **`line_controller.h`, `line_controller.cpp`**: the decisions. `estimateLine()` finds the line from the
   five sensors. The Normal PID mode uses PID with a gain schedule and a speed governor. The Full map
   modes add feed-forward from the plan, and the mixed mode adds sensor correction. `update()` returns
   the two wheel speeds. This file is the same on the robot and in the simulator.
7. **`world.h`, `world.cpp`**: the simulated robot. It moves the robot with physical forces (weight,
   friction, motor stall force, rolling loss, tyre slip and slide), senses the tape, and decides
   finished, derailed, stopped or timed out. Start here for the simulator.
8. **`wasm_exports.cpp`**: the C functions the web page calls, such as `run_start`, `run_advance`,
   `run_centre` and `headless_lap`.
9. **`LineFollower.ino`, `hardware.h`, `hardware.cpp`**: the real robot. `setup()` calibrates the sensors,
   and `loop()` runs the controller at 500 Hz. `hardware.*` holds the pin numbers, the sensor
   calibration and the motor driver.

## One control tick

```
sensors (5 values, 0 white to 1 black)
   -> estimateLine()            offset of the line, in metres
   -> LineController::update()  turn rate and speed, from the chosen mode
   -> left and right wheel speeds (m/s)
   -> the robot's motors (hardware.cpp on the real robot, World::actuate() in the simulator)
   -> the robot moves, and the sensors see the tape again
```

In the simulator, `World::tick()` runs this loop every 2 ms. `World::sense()` produces the sensor
values, `LineController::update()` picks the wheel speeds, `World::actuate()` applies the forces, and
`World::judge()` checks the outcome against the true position.

## Not included

- `tests/`, `tools/`, `web/` and `scripts/`: tests, the results exporter, the page and the build.
- `sim/wasm_runtime.cpp`: `memcpy` and `memset` for the WebAssembly build.
- `tests/hil/`: the mock Arduino API used to run the sketch on a computer.
